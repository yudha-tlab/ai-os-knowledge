1. # Inbox Pengajuan

User Story : Sebagai operator saya ingin melihat data pengajuan pembiayaan yang diajukan melalui aplikasi tapera, agar saya dapat melakukan follow up pengajuan.

1. ## Data Inbox Pengajuan

   1. ### Purpose/Description

Fitur ini digunakan untuk menampilkan data pengajuan yang diajukan oleh anggota tapera di luar sistem BSB Tapera, data ini ditampilkan agar bsb dapat menindaklanjuti pengajuan pembiayaan yang sudah diajukan oleh anggota tapera.

2. ### Use Case

| UC-1 | Data Inbox Pengajuan |
| :---- | :---- |
| **Primary Actor(s)** | Operator Cabang Bank Sumsel Babel |
| **Stakeholders and Interest** | Bank Sumsel Babel, BP Tapera |
| **Trigger** | Operator Cabang klik menu "Inbox Pengajuan" di aplikasi |
| **Pre-conditions** | Operator Cabang sudah login ke sistem  |
| **Post-conditions** | Data Inbox Pengajuan berhasil ditampilkan ke sistem BSB Tapera. |
| **Main Success Scenario** | 1\. Operator Cabang klik menu "Inbox Pengajuan" di aplikasi 2\. Sistem mengirim request ke API BP Tapera 3\. Sistem menampilkan data inbox pengajuan dari API BP Tapera  4\. Operator dapat melihat data inbox pengajuan |
| **Extensions** | 2a. Jika koneksi ke API BP Tapera gagal, sistem menampilkan pesan error dan menyarankan untuk mencoba lagi |
| **Priority** | High |
| **Special Requirements** |  |

2. ## Detail Inbox Pengajuan

   1. ### Purpose/Description

Fitur ini digunakan untuk menampilkan detail data pengajuan yang diajukan oleh anggota tapera di luar sistem BSB Tapera, data ini ditampilkan agar operator cabangdapat mengetahui detail data pengajuan.

2. ### Use Case

| UC-2 | Detail Inbox Pengajuan |
| :---- | :---- |
| **Primary Actor(s)** | Operator Cabang Bank Sumsel Babel |
| **Stakeholders and Interest** | Bank Sumsel Babel, BP Tapera |
| **Trigger** | Operator cabang memilih salah satu data pengajuan |
| **Pre-conditions** | Operator cabang sudah di dalam menu inbox pengajuan  |
| **Post-conditions** | Detail Pengajuan ditampilkan kepada operator cabang. |
| **Main Success Scenario** | 1\. Operator cabang memilih salah satu data "Inbox Pengajuan" 2\. Sistem mengirim request ke API BP Tapera 3\. Sistem menampilkan detail data inbox pengajuan dari API BP Tapera  4\. Sistem menampilkan data detail pengajuan 5\. Operator cabang melihat informasi detail data pengajuan |
| **Extensions** | 2a. Jika koneksi ke API BP Tapera gagal, sistem menampilkan pesan error dan menyarankan untuk mencoba lagi |
| **Priority** | High |
| **Special Requirements** |  |

   3. ### Mock Up

      4. ### Functional Requirement

| Spec ID | Specification Description | Business Rules/ Data Dependency |
| :---- | :---- | :---- |
| FR-1 | Sistem harus menerima parameter id Pengajuan | Salah satu parameter harus ada |
| FR-2 | Sistem harus memvalidasi parameter yang diterima | \- |
| FR-3 | Sistem harus mengambil data detail pengajuan pembiayaan | Data harus lengkap sesuai dengan spesifikasi |
| FR-4 | Sistem harus mengirimkan respons berupa detail lengkap pengajuan pembiayaan | Format respons harus sesuai dengan spesifikasi |
| FR-5 | Sistem harus menangani data sensitif dengan aman | Data seperti NIK dan NPWP harus dienkripsi |
